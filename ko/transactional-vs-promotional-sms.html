트랜잭션 vs 프로모션 SMS: 분류가 전송을 좌우하는 이유

통신사와 애그리게이터는 수신자 기대와 악용 위험이 다르기 때문에 SMS를 트랜잭션과 프로모션 트래픽으로 나눕니다. 이 분류가 등록, 라우팅, 필터링을 결정합니다. 캠페인을 잘못 표시하면 전송이 나빠집니다. 마법 같은 규칙 때문이 아니라, 유형을 다르게 다루는 콘텐츠 검사와 불만 신호 때문입니다.

업계에서 말하는 트랜잭션 vs 프로모션의 의미

트랜잭션 SMS는 수신자가 취한 행동이나 이미 유지 중인 관계 때문에 분명히 기대할 이유가 있는 트래픽입니다. 전형적인 사례는 일회용 비밀번호(OTP), 로그인 알림, 배송 업데이트, 사용자가 예약한 알림, 결제 영수증, 활성 서비스에 연결된 잔액·장애 공지입니다. 메시지는 사용자가 이미 만든 필요에 답합니다. 프로모션 SMS는 판매, 재참여, 혜택 안내를 위한 고객 연락입니다. 할인, 신제품 출시, 윈백 캠페인, 뉴스레터형 대량 발송, 대부분의 ‘보고 싶어요’ 문구가 해당합니다. 한때 수신 동의를 했어도 상업적 의도가 핵심입니다.

이 분류는 철학보다 운영에 가깝습니다. 네트워크, 허브, 기업 발신자는 모든 비즈니스 모델을 처음부터 파악하지 않고도 등록·처리량·콘텐츠 정책을 다르게 적용할 방법이 필요합니다. 트래픽을 트랜잭션 또는 프로모션으로 구분하는 것이 대략적인 운영 기준입니다. 완벽하지는 않고 경계 메시지도 있지만, API·발신자 ID·템플릿 체계가 이를 중심으로 구축될 만큼 안정적입니다. 메시징 API에서 제품 SKU, 라우트 플래그, 캠페인 유형을 고를 때 보통 어떤 유형을 보낸다고 선언하는 것입니다.

모호한 경우에는 수신자 주도 기대가 유용한 기준입니다. 사용자가 방금 코드를 요청했거나, 장바구니를 확인했거나, 보유 티켓 알림을 켰다면 메시지는 본질적으로 트랜잭션입니다. 영업 제안·추가 판매 유도·사용자가 방금 유발하지 않은 소식를 보낼 시점을 고른다면, CRM에 ‘고객’이라고 되어 있어도 프로모션으로 다루세요. 동의만으로 마케팅 문구가 트랜잭션 트래픽이 되지는 않습니다. 목적과 콘텐츠가 전송 시에도 중요합니다.

SMSRoute's 국가별 팩트 시트는 이 분류를 정확히 공식화하는 등록 체계를 운영하는 시장을 정리합니다.

라우트와 필터가 유형을 다르게 취급하는 이유

많은 시장에서 트랜잭션과 프로모션 스트림은 별도로 등록되거나 라우팅됩니다. 다른 발신자 ID, 다른 사전 승인 템플릿, 다른 단축번호·장번호, 중간 허브를 통한 다른 경로를 뜻할 수 있습니다. 프로모션 경로는 사전 템플릿 등록, 브랜드·발신자 등록, 명시적 캠페인 식별자가 더 자주 필요합니다. 트랜잭션 경로는 보통 저지연·고신뢰 신호에 맞춰 최적화됩니다. OTP·알림 트래픽은 짧고 시의적절하며 범위가 좁을 것으로 기대되므로, 강력한 피싱·스팸 필터는 거치되 마케팅 지향 검사 중 일부를 우회할 수 있습니다.

필터가 있는 이유는 대량 SMS가 악용 위험이 높은 채널이기 때문입니다. 프로모션 경로는 판매 언어, 목적지 링크, 알려진 스팸과의 패턴 유사성에 대해 더 공격적인 콘텐츠 스캔을 받습니다. 트랜잭션형 경로는 다른 실패 모드를 단속합니다. 신뢰 채널을 악용해 ‘알림’ 명목으로 광고·피싱·원치 않는 제안을 밀어넣는 경우입니다. 프로모션 콘텐츠가 트랜잭션으로 분류된 라우트에 나타나면, 중간 시스템과 단말기 측 분류기는 선언 목적과 페이로드의 불일치를 봅니다. 흔한 대응은 무음 필터링, 지연 전송, 템플릿 거부, 불만 가중치 상승입니다. API에서 HTTP 200으로 항상 보이는 완곡한 오류가 아니라, 단말기가 울리지 않는 경우입니다.

불확실성은 현실입니다. 정확한 임계값, 벤더 규칙, 국가 상호접속 정책은 다르고 변합니다. 단일 글로벌 체크리스트에 기대지 마세요. 변하지 않는 것은 질적 패턴입니다. 유형을 정직하게 선언하고, 라우트가 요구하는 등록을 하며, 콘텐츠를 그 유형에 맞추세요. 분류를 서류상 허구로 취급하는 것이 스테이징에서는 되던 캠페인이 프로덕션에서 멈추는 방식입니다.

메시지를 분류하는 콘텐츠 신호

다운스트림 시스템은 대개 CRM 맥락이 없습니다. 텍스트, 발신자 신원, 링크 평판, 발송 패턴, 사용자 불만 피드백으로 분류합니다. 강한 프로모션 신호에는 할인·세일 언어(‘% 할인’, ‘기간 한정’, ‘지금 구매’, ‘코드 사용’), 보안 사건이 아닌 혜택으로 포장한 긴급성, 제품 카탈로그 문구, 마케팅 CTA가 있습니다. 링크(특히 브랜드 단축 URL, 리다이렉트 체인, 평판이 얇은 도메인)는 두 유형 모두 심사를 높이지만 프로모와 피싱에서 특히 흔합니다. 수신 거부 푸터(‘STOP 회신’, ‘구독 취소’)는 마케팅 트래픽에 올바르고 종종 기대됩니다. 순수 OTP로 라벨링한 메시지에 있으면 그 자체가 유형 불일치로 보일 수 있습니다. 트랜잭션 OTP는 보통 캠페인 구독 취소 요소를 넣지 않기 때문입니다.

트랜잭션 신호는 반대입니다. 단일 목적, 짧은 숫자 코드, 구체적 이벤트(‘택배 배송 출발’, ‘결제 완료’, ‘새 기기 로그인 시도’), 최소한의 상업적 장식입니다. 연결(concatenation)은 일반 SMS 세그먼트 규칙을 따릅니다. 표준 GSM 단일 세그먼트 텍스트 160자, 연결 시 세그먼트당 153자, 단일 세그먼트 유니코드 70자, 유니코드 연결 시 세그먼트당 67자. 다만 길이만으로 유형이 정해지지는 않습니다. 긴 영수증도 트랜잭션일 수 있고, 짧은 ‘FLASH SALE’은 한 세그먼트에 맞아도 트랜잭션이 되지 않습니다.

E.164 목적지 형식(최대 15자리)과 깔끔한 API 동작(HTTP 200 같은 성공 응답, HTTP 429 시 백오프, 업스트림 HTTP 500 처리)은 연동 품질에 중요합니다. 콘텐츠 유형을 덮어쓰지는 않습니다. 본문이 프로모처럼 읽히면 MSISDN을 얼마나 신중히 정규화했든 필터는 프로모로 취급합니다.

SMSRoute 수신 거부 푸터 생성기는 15개 언어로 규정에 맞는 마케팅 푸터를 만듭니다.

필터링에도 통하는 실무 규칙

콘텐츠를 경로 목적에 맞추세요. 제품, 발신자 ID 또는 템플릿 세트가 트랜잭션용으로 등록·판매된 경우 OTP, 알림, 영수증만 해당 정의에 맞게 보내세요. 혜택, 론칭, 관계 유지 트래픽은 프로모션 등록과 프로모션 경로에 두세요. 혼합하면 submit API는 성공을 반환해도 “무작위”처럼 보이는 미전달 필터링을 받게 됩니다.

수신 거부 메커니즘은 마케팅에만 두세요. 프로모션 프로그램은 STOP 및 동등한 종료를 깔끔하고 신속히 존중해야 합니다. 트랜잭션 메시지는 특정 프로그램 설계상 정말 필요하지 않은 한 캠페인 수신 거부 문구를 넣지 마세요. 모든 OTP에 STOP을 넣으면 사용자와 필터가 마케팅으로 인식하게 됩니다. 트랜잭션 동의 문구를 광고 발송 허점으로 악용하지 마세요.

프로모션을 OTP나 보안 알림으로 위장하지 마세요. 일부 발신자가 기대하는 단기 전달률 상승은 안정적으로 나타나지 않지만, 장기 영향은 분명합니다. 콘텐츠 스캐너는 “코드” 메시지 안의 할인 문구와 위험 링크를 탐지합니다. 신뢰하던 알림이 실제로는 홍보일 때 수신자 신고율이 높아집니다. 신고와 불일치 신호는 향후 트래픽 전반, 정상 코드까지 발신자 신원에 대한 필터링을 강화합니다. 스트림을 분리하면 로그인·결제 흐름에 꼭 필요한 트랜잭션 평판을 보호합니다.

올바른 운영 관행이 분리를 뒷받침합니다. 채널이 허용하는 곳에서 별도 발신자 신원을 쓰고, 필요 시 템플릿을 승인받으며, 프로모션 문구는 등록된 패턴 안에 유지하세요. 어떤 경로도 전달을 보장한다고 가정하지 말고 전달 영수증과 오류 유형을 모니터링하세요. 모바일 메시징은 핸드셋·네트워크 결과가 가변적인 store-and-forward 방식입니다. 캠페인 성과가 부진하면 처리량만 탓하기 전에 유형 불일치와 콘텐츠 단서를 점검하세요. 정직한 라벨링, 담백한 OTP 문구, 마케팅답게 보이는 마케팅이 규칙이 다른 시장에서도 지속 가능한 전략입니다.

자주 묻는 질문

트랜잭션 SMS와 프로모션 SMS의 차이는 무엇인가요?
트랜잭션 SMS는 수신자가 본인 행동이나 활성 서비스로부터 기대하는 메시지입니다. OTP, 알림, 영수증, 예약 업데이트 등입니다. 프로모션 SMS는 마케팅으로, 혜택, 캠페인, 재참여 유도 및 판매자가 시점을 정하는 기타 상업 콘텐츠입니다. 기대치와 남용 위험이 다르므로 경로와 등록이 둘을 분리하는 경우가 많습니다.
트랜잭션 경로에서 프로모션 SMS가 필터링된 이유는 무엇인가요?
트랜잭션 스타일 경로와 템플릿은 신뢰 구간의 오남용을 감시합니다. OTP/알림으로 표시한 트래픽에 할인 문구, 마케팅 CTA, 프로모션 링크, 수신 거부 푸터가 있으면 목적 불일치가 생깁니다. 그러면 API가 submit을 수락했어도 필터와 신고 신호가 메시지를 지연·삭제·거부합니다.
OTP나 배송 SMS에 할인 혜택을 넣을 수 있나요?
넣지 마세요. 트랜잭션 문구에 프로모션을 섞는 것은 필터링과 사용자 신고를 유발하는 흔한 방식이며, 실제 코드·알림의 발신 평판을 해칠 수 있습니다. 트랜잭션 사실은 트랜잭션 경로로 보내고, 혜택은 적절한 수신 거부 처리가 된 프로모션 경로로 따로 보내세요.

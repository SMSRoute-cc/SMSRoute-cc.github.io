What the {value, source, retrieved} model means

Every fact on this page — a rate, a calling code, a sender-ID regime — is stored as a small record with three parts: the value itself, the source that backs it (a regulator, a carrier practice, or smsroute's own published per-country page), and the date it was retrieved. Nothing here is estimated or interpolated. If a fact changes, the source and date change with it, so you can judge how current a number is before you build on it.

The full dataset behind this tool is open and reusable: download countries.json (CC-BY 4.0). This page is a client-side view over that same file — the JSON embedded on this page is a byte-for-byte copy of it, so the tool works fully offline once loaded.

How segment sizes are computed

Charset class comes from comparing each country's dominant language against the GSM 03.38 default alphabet. GSM-7 messages get 160 characters in a single SMS, 153 per segment once concatenated. GSM-7 ext stays inside the same 160/153 budget but needs the GSM-7 extension table (2 septets instead of 1) for a few characters. UCS-2 applies when the script falls outside GSM-7 entirely — Cyrillic, CJK, Arabic script, or enough diacritics — dropping the budget to 70 characters single-segment, 67 per segment concatenated.

Frequently asked questions

What do GSM-7, GSM-7 extended, and UCS-2 mean for how long my SMS can be?

GSM-7 is the default SMS alphabet: 160 characters fit in one segment, 153 per segment once a message needs more than one (a 6-byte concatenation header eats the rest). A handful of characters live in a GSM-7 extension table and cost 2 septets instead of 1, but the message still encodes as GSM-7. Any character outside GSM-7 entirely — most non-Latin scripts, some accented letters — forces the whole message into UCS-2, which drops the budget to 70 characters single-segment, 67 per segment when concatenated.

Why do some countries require sender-ID pre-registration and others don't?

Regulators or carrier groups in some markets (India's TRAI DLT, the GCC pre-registration pattern, Singapore's SSIR, the US 10DLC framework) require alphanumeric sender IDs or campaign headers to be registered before traffic is allowed through, mainly to curb spoofing and spam. Other markets have no centralized registry and alphanumeric sender IDs are used by carrier convention alone. The regime column in the table above names the specific basis for each country.

How current are the rates and rules shown on this page?

Every field in this tool carries its own value/source/retrieved record, pulled from the open dataset linked above. Rates and calling codes were retrieved 2026-07-27; sender-ID practice notes were retrieved 2026-07-26. The retrieved date is shown next to every fact so you can judge freshness yourself rather than trust an undated claim.
